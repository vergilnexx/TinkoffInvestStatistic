# Централизованные каталоги результатов сборки

## Контекст

Android Debug-сборка не может создать Java Callable Wrapper по пути длиной 262 символа. Проблемный файл располагается глубоко внутри каталога проекта в `obj/Debug/net10.0-android36.0/android/src`. Несмотря на включённую в Windows поддержку длинных путей, используемая Xamarin/Android-задача обращается к файлу через реализацию `System.IO`, сохраняющую ограничение `MAX_PATH`.

## Цель

Сократить пути ко всем промежуточным файлам и результатам сборки решения, используя штатную централизованную структуру выходных данных .NET 8 и новее. Сборка должна работать из текущего расположения репозитория без локальной настройки виртуальных дисков или переноса исходного кода.

## Решение

В корне репозитория создаётся `Directory.Build.props`, применяемый ко всем проектам решения. Свойство `UseArtifactsOutput` получает значение `true`.

После изменения .NET SDK размещает выходные данные в общем каталоге `artifacts` рядом с `Directory.Build.props`:

- `artifacts/obj/<Project>/<Pivot>` — промежуточные и сгенерированные файлы;
- `artifacts/bin/<Project>/<Pivot>` — собранные бинарные файлы;
- другие типы результатов, например публикации и пакеты, используют соответствующие стандартные подкаталоги.

Имя проекта разделяет результаты разных проектов, а pivot разделяет конфигурации, целевые фреймворки и runtime identifier. Дополнительные пользовательские правила путей не вводятся.

## Совместимость и границы

Решение использует стандартный `UseArtifactsOutput`, поддерживаемый .NET 8 и более новыми SDK. Текущий проект использует .NET SDK 10, поэтому дополнительных зависимостей не требуется.

Существующие каталоги `bin` и `obj` не удаляются автоматически и больше не участвуют в новых сборках. Каталог `artifacts/` уже исключён корневым `.gitignore`, поэтому результаты сборки не попадут в Git.

Изменение не затрагивает исходный код приложения, формат APK, подпись релиза или данные на Android-устройстве.

## Проверка

После добавления `Directory.Build.props` необходимо:

1. запросить вычисленные MSBuild-свойства и убедиться, что промежуточные файлы направлены в корневой `artifacts/obj`;
2. выполнить Debug-сборку Android-проекта из текущего расположения репозитория;
3. подтвердить отсутствие прежней `DirectoryNotFoundException`;
4. убедиться, что Java Callable Wrappers созданы под `artifacts/obj`, а итоговые файлы — под `artifacts/bin`;
5. проверить, что Git не показывает содержимое `artifacts/` как неотслеживаемое.

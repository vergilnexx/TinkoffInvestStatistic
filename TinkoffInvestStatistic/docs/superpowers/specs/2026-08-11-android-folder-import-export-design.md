# Выбор папки для экспорта и импорта на Android

## Контекст

Сейчас экран экспорта пытается получить обычный путь к общей папке `Documents`, но Android-реализация `IFileSystemService` не разрешается через `DependencyService`. В результате приложение использует `FileSystem.AppDataDirectory` и сохраняет файлы в приватную папку `/data/user/0/<package>/files`, недоступную обычному файловому менеджеру. Простая запись по пути `/storage/emulated/0/...` также не является надёжным решением для современных версий Android из-за scoped storage.

## Цель

При каждой операции пользователь выбирает доступную папку в системном интерфейсе Android:

- экспорт создаёт в выбранной папке отдельные файлы для отмеченных категорий;
- импорт находит в выбранной папке самые новые файлы для отмеченных категорий;
- решение работает на Huawei и других актуальных Android без доступа ко всему внешнему хранилищу.

## Не входит в объём

- объединение данных в ZIP или другой единый архив;
- автоматическое запоминание выбранной папки;
- изменение XML-формата существующих экспортных файлов;
- поддержка платформ, отличных от текущей Android-цели проекта.

## Пользовательский интерфейс

Три флажка получают нейтральные подписи `Настройки`, `Данные` и `Зачисления`, поскольку они используются обеими операциями. Три отдельные кнопки выбора файлов импорта и строки с путями удаляются.

Кнопки `Экспортировать` и `Импортировать` остаются. После нажатия приложение проверяет, что выбрана хотя бы одна категория, и открывает системное окно выбора папки. Папка выбирается заново для каждой операции.

Если пользователь закрыл системное окно без выбора, операция тихо завершается без изменений и без сообщения об ошибке.

## Работа с хранилищем

Для выбора и доступа к папке используется Android Storage Access Framework с действием `ACTION_OPEN_DOCUMENT_TREE`. Результат является URI вида `content://`, а не обычным файловым путём. Чтение, перечисление и создание документов выполняются через `ContentResolver` и API документов Android.

Платформенная работа с URI скрывается за отдельным интерфейсом сервиса папок. ViewModel отвечает только за запуск выбора папки и отображение результата. `ExportService` продолжает отвечать за состав экспортируемых данных, имена файлов и восстановление данных. XML-сериализация должна работать с потоками, чтобы бизнес-логика не зависела от обычных файловых путей.

Разрешение `WRITE_EXTERNAL_STORAGE` удаляется из манифеста: выбранная пользователем папка предоставляет необходимый доступ через Storage Access Framework.

## Экспорт

После выбора папки для каждой отмеченной категории создаётся отдельный UTF-8 XML-файл с существующей схемой именования:

- `exported_Settings_dd.MM.yyyy.txt`;
- `exported_Data_dd.MM.yyyy.txt`;
- `exported_Transfers_dd.MM.yyyy.txt`.

Если файл с таким именем уже существует, его содержимое заменяется, чтобы повторный экспорт в тот же день не создавал дубликаты. Неотмеченные категории не экспортируются.

После успешного завершения приложение показывает имена созданных файлов. Если запись одного из файлов завершилась ошибкой, операция останавливается и сообщает, какой файл не удалось сохранить; уже созданные файлы не удаляются.

## Импорт

После выбора папки приложение перечисляет её документы и для каждой отмеченной категории рассматривает только имена соответствующего вида `exported_<Category>_dd.MM.yyyy.txt`. Файлы с неверным префиксом или датой игнорируются.

Для каждой категории выбирается файл с максимальной датой из имени. Если внешним способом созданы несколько документов одной категории с одинаковой максимальной датой, выбирается документ с наиболее поздним `LastModified`; при отсутствии этого значения выбор стабилизируется сортировкой по имени URI.

Найденные файлы читаются через `ContentResolver` и импортируются существующей логикой. Если для некоторых отмеченных категорий файлов нет, найденные категории импортируются, а итоговое сообщение перечисляет отсутствующие. Если не найден ни один подходящий файл, данные не изменяются и пользователь получает понятное сообщение.

Проверка биометрии/прав для категории `Зачисления` сохраняется в текущем виде и выполняется до выбора папки.

## Ошибки и безопасность данных

- Отмена выбора папки не считается ошибкой.
- Ошибка чтения или некорректный XML не должны очищать существующие данные соответствующей категории.
- Сообщения об ошибках содержат отображаемое имя проблемного файла, а не внутренний `content://` URI.
- Доступ к выбранной папке используется только на время текущей операции; URI не сохраняется между запусками.
- Импорт не удаляет экспортные файлы.

## Проверка

Автоматические тесты должны покрыть:

- формирование имён трёх типов файлов;
- замену одноимённого файла при повторном экспорте;
- выбор самого нового корректного файла каждой категории;
- игнорирование файлов с неверными именами и датами;
- частичный импорт при отсутствии отдельных категорий;
- отсутствие изменений при отмене выбора папки или ошибке десериализации;
- отсутствие запроса `WRITE_EXTERNAL_STORAGE` в итоговом манифесте.

Ручная проверка на Android/Huawei должна подтвердить, что выбранная папка видна в системном файловом менеджере, содержит созданные файлы и может быть выбрана для обратного импорта после перезапуска приложения.
